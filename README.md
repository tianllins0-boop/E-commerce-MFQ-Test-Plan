# E-commerce-MFQ-Test-Plan

基于 **MFQ（Models - Functional - Quality）** 框架的电商系统测试计划，覆盖商品（SPU/SKU）、库存、购物车、订单全生命周期（下单 → 支付 → 发货 → 签收 → 退货）以及与 WMS/SC2P 的外部同步。

## 我对 MFQ 框架的理解

| 层 | 回答的问题 | 在本项目中的落地 |
|---|---|---|
| **M - Models** | 系统"应该怎么转"？ | 5 个模型：E2E 业务流程、订单状态机、库存状态模型、外部交互模型、一致性边界。所有功能用例的 expected 直接引用模型，保证可追溯 |
| **F - Functional** | 功能"测什么"？ | 约 25 条用例（ID/优先级/前置/步骤/预期），含库存同步一致性专项（reserve/deduct/restore 成败、幂等、乱序、对账）与异常处理/补偿策略 |
| **Q - Quality** | 质量"保到什么程度"？ | 性能（秒杀 1 万并发零超卖）、可靠性（重试/熔断/补偿任务）、可观测（差异率/积压/卡单告警）、安全（越权/脱敏）、可恢复（故障演练/数据修复） |

核心设计思想：**先评模型、再评用例**；库存以不变式 `available + reserved + sold = 总库存` 为对账锚点；分布式异常"能重试的不丢单、不能自动修的必须能被对账发现"。
